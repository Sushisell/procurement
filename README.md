# Заявка на продукты

Мобильное веб-приложение для ежедневной заявки продуктов: справочники берутся из общей Google Таблицы, а отправленная заявка записывается в таблицу выбранного филиала.

## Что делает приложение

- Загружает филиалы, сотрудников, цены, шаблон заявки и информацию о поставщиках из общей Google Таблицы.
- Может работать двумя способами:
  - как обычное веб-приложение Google Apps Script;
  - как статический сайт на GitHub Pages, который читает и отправляет данные через опубликованный Apps Script API.
- Показывает сотруднику мобильный сценарий: филиал → ФИО → дата → вкладки поставщиков.
- Компактно показывает блок выбора филиала, ФИО и даты, чтобы заявка занимала меньше места на телефоне.
- Для каждого поставщика показывает отдельную вкладку, контакты, минимальную сумму заявки и условия заявки.
- Фиксирует минималку и сумму заявки рядом с заголовками таблицы товаров, чтобы они оставались видимыми во время заполнения.
- Делает телефонные номера кликабельными через `tel:`.
- Считает сумму по каждому поставщику и общую сумму заявки на телефоне до отправки.
- При отправке находит таблицу выбранного филиала и заполняет в ней дату, ФИО, сумму заявки и количества по товарам.
- При синхронизации шаблона с филиальной таблицей не удаляет старые строки: товары, которых больше нет в шаблоне, подсвечиваются серым.

## Файлы

- `Code.gs` — серверная часть Apps Script: HTML-страница, JSON API, чтение справочников, подготовка листа филиала, запись заявки.
- `index.html` — мобильный интерфейс веб-приложения. Работает и внутри Apps Script, и на GitHub Pages.

## Вариант 1. Запуск только через Google Apps Script

1. Откройте общую Google Таблицу закупок.
2. Перейдите в **Расширения → Apps Script**.
3. Создайте файлы `Code.gs` и `index.html` и вставьте содержимое файлов из этого репозитория.
4. В Apps Script откройте **Project Settings → Script properties** и добавьте свойство:

   ```text
   MASTER_SPREADSHEET_ID = ID_ОБЩЕЙ_ТАБЛИЦЫ
   ```

   ID — это часть ссылки между `/d/` и `/edit`.

5. Нажмите **Deploy → New deployment → Web app**.
6. Укажите:
   - **Execute as:** Me / Владелец скрипта.
   - **Who has access:** Anyone with the link или пользователи вашего домена.
7. Выдайте скрипту доступ к Google Sheets при первом запуске.

## Вариант 2. Сайт на GitHub Pages + Google Таблица как API

1. Выполните шаги из раздела Apps Script и опубликуйте веб-приложение.
2. Скопируйте URL деплоя Apps Script вида:

   ```text
   https://script.google.com/macros/s/DEPLOYMENT_ID/exec
   ```

3. Загрузите этот репозиторий на GitHub.
4. В GitHub откройте **Settings → Pages** и включите публикацию из нужной ветки/папки, где лежит `index.html`.
5. Откройте сайт GitHub Pages с параметром `api`:

   ```text
   https://USER.github.io/REPOSITORY/?api=https://script.google.com/macros/s/DEPLOYMENT_ID/exec
   ```

   Интерфейс на GitHub Pages будет:
   - получать справочники запросом `GET .../exec?action=bootstrap`;
   - отправлять заявку запросом `POST .../exec?action=submit`.

6. Если не хотите передавать `api` в адресной строке, перед публикацией можно задать URL в `index.html` через глобальную переменную:

   ```html
   <script>
     window.PROCUREMENT_API_URL = 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec';
   </script>
   ```

   Эту строку нужно поставить до основного скрипта приложения.

## API Apps Script

После деплоя веб-приложения доступны два действия:

- `GET /exec?action=bootstrap` — возвращает филиалы, сотрудников, поставщиков, каталог и текущую дату.
- `POST /exec?action=submit` — принимает JSON заявки и записывает ее в таблицу филиала.

Формат ответа одинаковый:

```json
{
  "ok": true,
  "data": {}
}
```

При ошибке:

```json
{
  "ok": false,
  "error": "Описание ошибки"
}
```

## Ожидаемая структура общей таблицы

### Лист `Цены`

| A | B | C | D |
|---|---|---|---|
| Поставщик | Товар | Цена | Кратность |

### Лист `Шаблон`

Поддерживается структура как на скриншоте:

- строка-заголовок поставщика — крупный текст поставщика в колонке A;
- ниже товары поставщика в колонке A;
- цена в колонке B;
- кратность в колонке C.

### Лист `О поставщике`

| A | B | C | D |
|---|---|---|---|
| Название | Контакт | Минималка | О заявке |

В колонке `Контакт` можно писать несколько телефонов в одной ячейке. Интерфейс автоматически сделает номера кликабельными.

### Лист `Сотрудники` или `Инфо`

Для сотрудников:

| A | B |
|---|---|
| Филиал | ФИО |

Для списка таблиц филиалов:

| D | E |
|---|---|
| Список филиалов | Ссылка на таблицу филиала |

## Ожидаемая структура таблицы филиала

Скрипт работает с месячным листом в формате `MM.yy`, например `06.26`.

- Колонка `C` — товар.
- Колонка `D` — цена на сегодня.
- Колонка `E` — кратность / цена за упаковку.
- Начиная с колонки `F` идут даты месяца.
- В строке `3` под датой записывается инициатор заявки.
- В строке `4` под датой записывается сумма заявки.
- В строках товаров под датой записываются количества.

Если лист месяца отсутствует, скрипт создаст его из шаблона общей таблицы.

## Что еще нужно, чтобы это стабильно работало

1. Дать владельцу Apps Script права редактора на все таблицы филиалов.
2. Заполнить ссылки на таблицы филиалов на листе `Инфо`/`Сотрудники` в колонках `D:E`.
3. Проверить, что названия филиалов в списке сотрудников и в списке ссылок совпадают символ-в-символ.
4. Проверить, что названия поставщиков в `Цены`, `Шаблон` и `О поставщике` совпадают символ-в-символ.
5. Определиться, можно ли одной датой перезаписывать заявку филиала. Сейчас повторная отправка на ту же дату очищает старые количества в колонке этой даты и записывает новую заявку.
6. Если у филиалов уже есть нестандартные листы, нужно один раз привести их к структуре из раздела выше или адаптировать константы в `Code.gs`.
